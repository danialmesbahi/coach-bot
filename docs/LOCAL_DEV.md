# اجرای لوکال با ربات تست

ربات اصلی (`isensir_bot`) روی سرور با **webhook** کار می‌کند. Docker لوکال ربات را با **polling** اجرا می‌کند و polling اول `deleteWebhook` را صدا می‌زند. اگر لوکال با همان توکن ربات اصلی بالا بیاید، وب‌هوک سرور پاک می‌شود و ربات اصلی تا ری‌استارت بعدی ربات روی سرور هیچ پیامی نمی‌گیرد. برای همین لوکال همیشه با یک ربات تست جداگانه اجرا می‌شود.

## یک بار: ساخت ربات تست

1. در تلگرام به `@BotFather` پیام بده، `/newbot` را بزن و یک اسم مثل `sensi_dev_bot` انتخاب کن.
2. توکنی که می‌دهد را فقط در فایل `.env` لوکال بگذار. این فایل در git نیست. توکن را جایی کپی یا ارسال نکن.

   ```
   BOT_TOKEN=<توکن ربات تست>
   BOT_USERNAME=sensi_dev_bot
   ```
3. در `.env` و `.env.live` لوکال این مقدارها را نگه دار:

   ```
   APP_ENV=development
   PAYMENT_MODE=mock
   PUBLIC_BASE_URL=
   ZARINPAL_MERCHANT_ID=
   ```
   `SENSI_ID` و `ADMIN_TEAM_IDS` را روی آیدی عددی تلگرام خودت بگذار تا بتوانی نقش‌ها را تست کنی.

هیچ‌وقت `.env.live` سرور را روی کامپیوتر کپی نکن.

## اجرا

```bash
docker compose up -d --build postgres redis bot web-api web
```

بعد در تلگرام به ربات تست `/start` بده.

## قفل‌های ایمنی در کد

- **وب‌هوک:** وقتی ربات در حالت توسعه بالا می‌آید، قبل از هر کار دیگری `getWebhookInfo` را می‌پرسد. اگر توکن وب‌هوک فعال داشته باشد (یعنی توکن ربات اصلی است)، ربات با خطا متوقف می‌شود و به ربات اصلی دست نمی‌زند. فقط وقتی عمداً می‌خواهی وب‌هوک یک ربات تست قدیمی را برداری، `ALLOW_WEBHOOK_TAKEOVER=true` بگذار. این را هرگز برای توکن ربات اصلی نگذار.
- **پرداخت:** با `PAYMENT_MODE=mock` هیچ درگاهی صدا زده نمی‌شود. حتی اگر در لوکال `zarinpal` بگذاری، بیرون از `APP_ENV=production` همه درخواست‌ها به `sandbox.zarinpal.com` می‌روند و پول واقعی جابه‌جا نمی‌شود.
- **کال‌بک:** لوکال سرور webhook ندارد و آدرس `/payment/zarinpal/callback` را باز نمی‌کند، پس کال‌بک واقعی زرین‌پال هیچ‌وقت به لوکال نمی‌رسد.
