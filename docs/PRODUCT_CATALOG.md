# Product catalog and channel subscriptions

Leaders and platform accounts manage **Products / مدیریت دوره‌ها** (`/catalog`). Staff cannot acquire this permission through custom roles.

## Configure a product

- Set title, description, price in Toman and duration: days, weeks, months (30 days), years (365 days), lifetime or one-time. Lifetime never expires; one-time is for ready-made delivery, not recurring channel access.
- **Arrange products** supports pointer/touch drag handles and keyboard/arrow controls. Position is saved in the same order Telegram uses. The editor offers visual “before this product / end of storefront” choices, not numeric ranks.
- Select the required questionnaire fields. Stored static profile details are reused. Body assessment fields include six measurements in cm; selecting photos also includes gender. Each purchase/renewal requires newly submitted measurements/photos, independent from older orders. Men must submit four directional photos; women can skip photos (up to six total). Products without assessment fields are exempt. The free-text custom-question editor is removed. New/saved products submit an empty question list; historical order snapshots and answers remain intact. Existing products are not silently rewritten until the coach saves them.
- Choose **Custom program**, **Ready-made content**, or **Private channel**.
- Custom programs enter the coach review/design workflow. Ready-made products support multiple files, HTTPS links and messages. Catalog uploads accept coach-selected formats, including MOV, HEIC and other attachments. Known preview formats retain content/extension checks; other nonempty files are stored as opaque attachments, never executed, extracted or rendered inline. Downloads force attachment/octet-stream with nosniff. This is not a malware scanner; coaches remain responsible for what they distribute. New files stream into the private `catalogfiles` Docker volume; legacy PostgreSQL attachments remain readable. Other upload areas keep their existing limits and allow-lists.
- There is no fixed catalog per-file size ceiling. Two concurrent uploads, 30-second idle deadlines and a per-chunk disk check keep at least 20% of the volume (minimum 1 GiB) free. If capacity is insufficient, the partial file is removed and the UI reports the failure. Interrupted transfers restart; completed files stay in the unsaved editor draft. Save the product before closing it.
- One-time means **deliver once after payment**, not a required one-use download URL. Files up to 50 MB each go directly from our private storage to Telegram, including multi-file one-time products; no public domain is required. Successful attachments are checkpointed. Requesting a completed one-time purchase again points the buyer to their original delivery, without resending it. External content URLs are sent as supplied.
- Telegram's hosted Bot API accepts new document uploads up to 50 MB. Larger uncached files still need purchase-bound downloads from this server: configure `PUBLIC_BASE_URL` in `.env.live` to a public HTTPS origin routing `/content/` to ingress. A localhost/Tailscale-only origin is not accessible to public buyers. Publishing such large-file products is blocked without this setup, while uploads and drafts remain available. This does not apply to the size of the whole bundle, only each file. Cached Telegram file IDs bypass re-upload.
- The upload picker supports multiple files and desktop drag/drop. New uploads use local preview URLs (released on removal/close), while reopening the editor uses a role-checked, range-capable `/api/catalog-assets/{id}/preview`. Only signature-validated raster images/videos are served inline, never arbitrary attachments. Unsupported device codecs/formats show a file fallback and do not prevent delivery. The shared media viewer supplies playback, image zoom and pan.
- Download links expire after two days and can be requested again from the bot while the purchase is valid. A GET preview never consumes a one-time purchase: the explicit download button redeems it, then a one-hour private cookie supports range requests/retries. Multiple tokens cannot bypass consumption. Consumed one-time content cannot be reissued. External destinations must enforce their own one-time use after redirect; this panel cannot revoke a third-party URL or an already downloaded file.
- Back up the **catalogfiles volume as well as PostgreSQL**. Archiving a product never deletes purchased files. Unattached completed uploads are retained; review references before reclaiming storage.
- Choose **Visible for sale** or **Hidden / draft**, then save to apply. The editor always shows storefront placement, with a keep-current-position option. Archive opens a separate confirmation dialog and removes the product from sale without deleting previous orders or entitlements. The editor's content scrolls independently of its header and action bar so notices cannot cover Save/Archive.

An order freezes price, title, duration, selected questions and delivery configuration. Changes affect future purchases only. An in-progress questionnaire must be restarted when its product changes before payment. Existing invoices remain payable at their original terms.

## Connect a private channel

1. Use a private channel dedicated to paid membership. Make the bot an administrator with **Invite users** and **Ban/restrict users** rights.
2. In a channel product, enter the channel's numerical `-100…` ID and select **Verify & connect**.
3. Only a verified payment creates an entitlement. The bot sends a time-limited join-request link, checks the Telegram ID against the buyer, approves that account, and consumes/revokes the link. Forwarding the link does not grant access to another account.
4. Renewals extend the remaining subscription in the same channel. Customers can request another invitation through their order's download/access action if the invitation expired.
5. Membership changes are processed immediately. Tracked members are checked every eight hours; expired members are banned unless another current paid entitlement covers that channel. Admins and bots are exempt.

**Telegram limitation:** Bot API cannot enumerate all existing channel members. Use an empty channel for strict membership control; events received after connection and recorded buyers can be managed. Unknown pre-existing members or events Telegram no longer retains cannot be retrospectively enumerated. Removing bot permissions also prevents enforcement; the panel reports failed checks.

## Delivery reliability

Custom-program delivery accepts a text note, up to 20 HTTPS links and up to 10 files in one bundle; each part is optional but at least one is required. The coach can submit a text-only, link-only or file-only delivery. The server stores the full bundle before the bot sends it, checkpoints each successfully sent part and marks the order delivered only after every part succeeds. Uncertain delivery pauses for explicit staff review; Telegram flood rejections are retried at most five times. Manual uploads retain the configured per-file limit (up to Telegram's 50 MB direct-upload limit). Ready-made products use the same text/files/multiple-link choices, frozen in each purchased order.

The old recurring motivational sender is removed. Leader/platform users instead open **Broadcasts**, select all bot customers or filter by paid purchase, one or more products, active entitlement and recorded age range. The panel previews the count and requires a second confirmation. A database snapshot queues recipients; the bot sends at a conservative rate and records sent/failed/paused counts. Team accounts are excluded. Ambiguous transport failures pause rather than blindly repeat. No broadcast is sent by the test suite.

Verified payments are processed from a durable PostgreSQL queue, with bounded batches and per-order locks. Each successfully sent file is independently checkpointed, including Telegram responses that classify a WEBP as a sticker. Only definite Telegram flood rejections retry automatically (at most six failed attempts). Other failures pause delivery to avoid duplicate sends; authorized staff can inspect diagnostics/received messages and explicitly retry from order details. The worker lives in the bot process. It does not request gateway verification again or count a second sale. Card transfers and manual receipt approval are retired. Historical receipts remain view-only; gateway verification remains server-side.

Multi-file delivery checkpoints each successful file independently; failure on a later attachment resumes from that point. Telegram does not provide an idempotency key for message sends: a crash between the send and its checkpoint can still repeat that single attachment. The order and entitlement remain singular. Internal delivery errors appear on the order, and channel errors appear in product settings. No real channel or purchase is created by the automated tests.
