# Feature-branch integration review — 2026-09-15

Branch: `feature/next-improvements`. Existing Graphify references were used to locate shared staff, order, message, catalog and audit paths; current source and runnable checks are the evidence, not stale graph line numbers.

## Corrected integration paths

| Path | Problem | Change |
| --- | --- | --- |
| Follow-up / client / task → chat | Live refresh depended on the underlying page's table filter | Drawer has an independent refresh signal; message events target the open user. Superseded detail reads are aborted. |
| Shared notes → assignment | Assigning erased unsent text; stale reads could overwrite a successful write | Preserve drafts across assignment, preserve newer typing during note submission, cancel stale reads and prevent overlapping mutations. |
| High event volume → UI / database | Every assignment requested a list; every streamed event re-read the session | UI batches updates every two seconds with one badge request in flight; server validates each bounded 100 ms event batch before sending. |
| Stream queue overflow → stale UI | Old events could disappear silently | Bounded queue emits a content-free resync marker; UI refreshes current data and counts. |
| Catalog → tasks → order details | Automatic purchases appeared as manual design work | Dedicated automatic-delivery filter, correct review counts, two-step progress and no empty design sections for instant products. |
| Edited catalog → historic task / follow-up | Search and follow-up title used today's product name | Use the purchased title snapshot, matching invoice and detail views. |
| Chat → client profile | Support-only staff could click an inaccessible profile | Profile link is disabled without client-read permission; backend authorization remains authoritative. |
| Reading chat history → new message | Incoming messages/media could jump to the bottom | Preserve reading position away from the latest messages; sending follows the latest message. |
| Mobile → secondary workspaces | Eight navigation icons competed for space | Up to four primary destinations plus a labelled More sheet, with follow-up badge and native modal focus handling. |
| Product editor on phone/tablet | Long form, low-visibility archive confirmation, unclear validation | Section shortcuts, 44 px choice targets, sticky confirmation, field-specific content errors, background scroll lock and disabled editor during writes. |
| Channel setup → Telegram | Repeated checks could occupy outbound calls | Six checks/minute/account, two concurrent checks/process, bounded request body and timeout. Catalog JSON is bounded to 32 KiB. |

The UI/UX skill influenced touch targets, compact navigation, section hierarchy and preservation of the existing design tokens. No new dependency or independent design system was added.

## Remaining release checks / known ceilings

- Physical iPhone/iPad PWA keyboard, orientation, safe-area and gesture testing still requires those devices. Desktop emulation cannot certify iOS keyboard behavior.
- Real ZarinPal, Telegram channels and failure-after-remote-send scenarios require controlled staging credentials/accounts. Telegram send has no distributed exactly-once guarantee; see `PRODUCT_CATALOG.md`.
- SSE currently caps at 64 simultaneous staff streams/process; this is not the Telegram bot-user count. Multi-tab staff sessions share the API account limit. Size real deployment capacity with sustained HTTP/bot load tests on production-equivalent hardware.
- Existing latest-message window and bounded member menus were retained; this review does not claim every historical record is browsable in one screen.
- Temporary benchmark databases were removed. No production schema or customer records were changed for testing.
